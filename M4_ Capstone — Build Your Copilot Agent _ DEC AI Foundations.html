🧠 Part 1: What is a Copilot Agent?

▼

From Copilot Chat to Custom Agent — The Evolution

In Modules 1-3, you used Copilot Chat — typing prompts one at a time and getting responses. That's powerful, but it requires you to remember the right prompt every time. A Copilot Agent is the next level: a custom AI assistant that already knows its job, has access to your company data, and follows your rules — without you needing to write a prompt each time.

Anatomy of a Copilot Agent

Every agent has 3 core components:

📝 Instructions

Who the agent is, how it behaves, what tone it uses, what it should and shouldn't do. Like writing a job description for an AI employee.

📚 Knowledge

Documents, SharePoint sites, Excel files, PDFs the agent can reference. This is what makes it "know" about DEC Infra — grounded on YOUR data.

⚡ Actions

Things the agent can DO — run Power Automate flows, query databases, create tasks, send emails. Turns the agent from answering questions to completing work.

1

Open Copilot Agent Builder

Go to microsoft365.com/chat → Click "Create an agent" in the left sidebar. Or go to copilotstudio.microsoft.com → Click "Create" → "New agent".

2

Write the Agent Instructions

This is the most important step. The instructions define WHO the agent is and HOW it behaves. Paste this into the Instructions field:

AGENT INSTRUCTIONS — COPY-PASTE
You are DEC Budget Analyst, an AI assistant for DEC Infra Projects Pvt Ltd, a construction company based in Hyderabad. YOUR ROLE: - Answer budget and cost questions about DEC Infra's construction projects - Analyze budget data, identify overruns, flag risks, and compare vendor rates - Help Project Managers and Finance teams make data-driven decisions BEHAVIOR RULES: - Always base answers on the uploaded project data — never make up numbers - If you don't have data to answer a question, say "I don't have that data in my knowledge base" - Present numbers in Indian Lacs (₹ Lac) format - Use 🔴🟡🟢 traffic lights for status indicators - Be concise — executives want answers in 2-3 sentences, not paragraphs - When showing comparisons, use tables - Always mention which project and line item you're referring to WHAT YOU CAN DO: - Portfolio risk scan (flag items >100% spent) - Cross-project vendor rate comparison - Contingency health check per project - Budget vs actual variance analysis - Invoice and payment gap analysis - Generate board-level dashboards WHAT YOU CANNOT DO: - Make procurement decisions (you recommend, humans decide) - Access real-time ERP data (you work from uploaded snapshots) - Share data with people outside DEC Infra - Provide legal or contractual advice TONE: Professional, direct, data-driven. Like a senior finance analyst presenting to the CEO.
3

Add Knowledge Sources

Upload or connect these files so the agent can reference them:

  • DEC_Infra_Master_Dataset_180rows.csv — Upload to SharePoint, then add as knowledge source
  • Vendor rate cards (if available) — PDF or Excel on SharePoint
  • Project schedule summaries — any Excel/PDF on SharePoint
  • Company policies (optional) — procurement policy, approval matrix
How to add knowledge: In Copilot Studio → Agent → Knowledge → Add → SharePoint site or Upload files. In Agent Builder → click "Add knowledge" → select files or paste SharePoint URL.
4

Test the Agent

Use the preview panel to ask test questions. The agent should answer from your data:

Test Questions to Try:

  • "Which projects have items over 100% budget?"
  • "Compare rebar rates across all projects"
  • "What's the contingency status for Kamareddy Auditorium?"
  • "Give me a portfolio risk summary for the CEO"
  • "How much are we overspending on HVAC across projects?"
  • "What's the total pending invoice amount?"
5

Publish to Teams

Once tested, publish the agent so your team can access it in Microsoft Teams:

Copilot Studio: Publish → Channels → Microsoft Teams → Turn on → Share with team/org.
Agent Builder: Click "Share" → Select users or groups → Done.

✅ Result: Any DEC Infra PM can now open Teams, type "Hey DEC Budget Analyst, which projects are over budget?" and get an instant, data-backed answer — no prompt engineering needed.

🎯 Part 6: Agent Building Best Practices

▼

✅ Do's and Don'ts for Agent Instructions

✅ DO

  • Define a clear role: "You are a budget analyst for..."
  • Set explicit boundaries: "You can/cannot..."
  • Specify output format: "Use tables, ₹ Lac format..."
  • Include safety catches: "If unsure, say so"
  • Define tone: "Professional, concise, data-driven"
  • Add examples of good responses

❌ DON'T

  • Write vague instructions: "Be helpful" (too generic)
  • Skip scope boundaries (agent will hallucinate)
  • Let agent access data it shouldn't see
  • Forget to say "verify before official use"
  • Deploy without testing at least 10 questions
  • Share agents externally without IT approval

Knowledge Source Best Practices

Source TypeBest PracticeDEC Infra Example
SharePoint SitePoint to a dedicated folder, not entire site/Projects/BudgetData/ (not entire SharePoint)
Excel / CSVClean headers, no merged cells, under 10MB242-row dataset with clear column names
PDFsUse text-based PDFs, not scanned imagesSafety standards, policy documents
Word DocsUse headings and structure for better parsingCompany handbook with H1/H2/H3 headings

Security & Data Protection for Agents

⚠️ Agents inherit access permissions. If the agent is grounded on a SharePoint folder, users can only see data they already have access to. But verify this before deploying.
  • Turn off "Search all websites" — enabled by default in Copilot Studio. Disable it for internal agents to prevent data leakage
  • Restrict sharing — share agents only with the team that needs them, not the entire organization
  • Review knowledge scope — make sure the agent can't access HR data, salary sheets, or Tier 3 confidential data unless specifically intended
  • Test with a non-admin account — verify the agent shows the right data to regular users
  • Audit regularly — check agent usage logs monthly for unexpected queries
